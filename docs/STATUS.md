# 기능별 메모

기능마다 동작 요약, 확인된 게임 동작, 실기 기록. 단계별 흐름은 각 모듈 머리말(docstring)에 있다 — 여기에는 요약과 코드에 남지 않는
사실만 적는다. 코드 구조·공통 부품은 `docs/ARCHITECTURE.md`. 마지막 정리 2026-11-15.

## 일일 숙제 (`mabi/runner.py`, `mabi/tasks/`)
실행기는 캐릭터마다 접속한 뒤 `[run] order`(캐릭터별 `[run.tasks_by_slot]`) 순서로 숙제를 하고, 숙제마다 끝났는지 다시 확인한다
(`tasks.VERIFY` — 숙제가 스스로 확인했으면 `bot.verified` 로 건너뜀). 주간·기타 숙제도 같은 실행기로 돈다 (카드의 `only`).

| 태스크 id | 내용 |
|---|---|
| weekday_dungeon | J → 아르바이트 탭 → 요일 던전 '이동' → 입장 → 추가 루팅 3회 |
| silver | 은동전 20개 단위로 사냥터/던전 |
| tribute | 고난도 심층 공략 퀘스트 → 심층 던전(매우 어려움) |
| black_hole | `/` 가이드 → 검은 구멍 바로 가기 → 클리어까지 대기 |
| daily_mission | N → 선물 받기 → 음식·연금술 미션 → 2/4/6회 누적 보상 |
| arbeit | 퀘스트 창(J) 아르바이트 탭의 일을 위에서부터 (상황 대응은 점검자) |

끝났는지는 패킷 → CLI → 화면 순 (2026-10-25):
- 검은 구멍: 맵에 들어갈 때마다 오는 '깬 검은 구멍' 목록에 오늘(6시 뒤) 나온 구멍이 있으면 완료. 없으면 가이드 화면.
  숙제를 시작할 때는 일일 달성 체크를 열지 않고 바로 가기만 연다 (끝냈으면 카드가 없다) — 가이드를 한 번만 연다.
- 요일 던전: 퀘스트 창 추천 항목이 요일 던전이면 '아직 안 함' (가이드를 열지 않는다). 아니면 가이드 화면.
  던전을 깨면 그걸로 완료.
- 은동전·공물·일일 미션·아르바이트: CLI.

### 은동전 (silver)
- 1단위(20개)뿐이면 던전 1회, 2단위 이상이면 사냥터 `field_runs` 회 + 나머지 던전.
- 캐릭터별로 `[silver.by_slot.N]` 로 바꿀 수 있습니다 (던전만 / 사냥터만 / 사냥터 장소 / 던전 종류·층·구역·난이도).
  화면의 캐릭터 탭 카드의 설정 창이 이 표를 고칩니다 (공통 설정과 다른 값만 남김).
- 입장 버튼 가격을 OCR 로 확인해서 20(소탕 10 + 더블 루팅 10)이 아니면 들어가지 않습니다.
  가격 숫자는 Windows OCR, '입장하기'·'임무 시작' 글자는 RapidOCR 과 Windows OCR 중 하나라도 맞으면 됩니다 (docs/ARCHITECTURE.md 'OCR 규칙').
- 한 판도 클리어하지 못하고 진행 불가(지역 맵에서 장소를 못 고름 등)가 있으면 실패로 끝내고 까닭을 남긴다. 은동전이 그대로라고
  같은 실패로 한 바퀴 더 돌지 않는다 (2026-11-14 — 데스크톱 메이트 창이 지역 맵 목록을 가렸다).

### 사냥터 안 검은 구멍
- 검은 구멍은 사냥터 안에 30분마다 3개 나오고, 다 깨면 30분 동안 못 들어갑니다. 그래서 하루 1회만 갑니다.
- 은동전 사냥터에 들어가면 (`[silver] black_hole_in_field = true`) 검은 구멍부터 처리하고,
  끝나면 사냥터 임무가 자동으로 이어집니다. 성공하면 뒤쪽 `black_hole` 태스크는 "이미 완료"로 건너뜁니다.
- 사냥터 안 검은 구멍이 실패하면 사냥터는 그대로 진행하고 `black_hole` 태스크에서 다시 시도합니다.
- 캐릭터 탭에서 검은 구멍을 끈 캐릭터는 `[run.skip_by_slot]` 로 `black_hole` 태스크를 빼고,
  `black_hole_in_field = false` 로 사냥터 안 검은 구멍도 하지 않습니다.

### 일일 미션
- 미션 종류는 날마다 다르며, 목록과 진행 상태는 CLI `get_daily_missions` 로 읽습니다.
- 음식 N개 먹기: 배고프지 않으면 B 로 못 먹으므로 미션 '진행하기' → 음식 탭 → 여행자 간식 → 사용하기(Space).
- 연금술 3회: '진행하기' → 보석 연금술 → 재료 자동 넣기 → **모두 승급 1회만** → ESC 로 미션 창 복귀.
  승급 직후 다음 단계 '모두 승급'(훨씬 비쌈)이 바로 뜨므로 두 번 누르면 안 됩니다.
- 그 외 미완료 미션은 결과 요약에 남깁니다.
- 선물 받기: CLI 가 '다 했는데 선물 안 받음'이라는 미션이 없어질 때까지 목록을 맨 위부터 휠 3칸씩 내려가며
  '선물 받기'를 하나씩 누르고, 받아졌는지는 패킷(받기 성공) → CLI 로 본다. 예전엔 10칸씩 크게 내려 가운데 줄을
  건너뛰어 11개 중 4개만 받았다 (2026-10-25). 연금술·채집 완료도 패킷 '미션 완료' 알림으로 바로 안다.
  남으면 창을 새로 열어 다시 훑는다 (새로 열면 받을 카드가 맨 위로 모인다. 연금술에서 ESC 로 돌아온 창에서 맨 윗줄 2개를
  못 찾은 적이 있다). 버튼은 창이 열리는 연출 중 점수가 0.74 까지 떨어져 한 장만 보고 없다고 하지 않는다.
  그래도 남으면 미션 창 스크린샷(dm_missed)을 남긴다.
- 캐릭터 숙제가 다 끝난 뒤 받을 선물이 있으면 (일일 미션 뒤 아르바이트 → '따뜻한 손길' 등) CLI 로 보고 그것만 받는다.

### 아르바이트 (`mabi/tasks/arbeit.py`)
- 일마다 흐름이 제각각이라 순서를 따라가지 않고, 상황 대응(수락·결과 보고·전달 창·대화·채집·제작·가공 창)은 점검자에게 맡기고
  태스크는 진척만 본다. 진행은 퀘스트 창(J)의 '진행하기' 로 한다 (추적 칸 클릭으로 바꾸지 않는다).
- '보유' 조건을 못 채운 일은 '구하는 방법' 맨 위(추천)로 필요한 만큼만 채집한다. 구할 방법이 없거나 가공 시설 칸이 꽉 차면 그 일은 건너뛴다.

## 주간 숙제 (숙제 탭 > 주간 숙제)
캐릭터마다 이번 주 1번. 끝냈는지는 CLI 성장 가이드의 Weekly IsCompleted 가 먼저다.

### 고정 파티 어비스 (`mabi/tasks/party.py`, 11-20)
- 어비스 탭 모드에서 '고정 파티장' · '고정 파티원' 을 고른다 (카드 `partyRole` → `[abyss] party_role`). 파티는 게임에서 미리 맺어 둔다.
- 파티장: 함께하기 탭 → 우연한 만남 끔 → 입장하기 → 인원이 모자라면 '도전하시겠습니까?' 에 도전하기 → 준비 UI 에서 파티원을 기다려 입장.
  클리어 뒤 다시 하기도 같다. 파티원: 준비 UI 가 뜨면(패킷 내 상태 1 또는 화면 '준비 완료') Space, 클리어 화면에선 파티장을 기다린다.
- 파티가 4명이 안 되면 (사용자 11-22): 파티장은 우연한 만남을 켜고 입장해 빈자리를 채운다 (준비 UI 없음). 클리어 뒤엔 다시 하기 대신
  '다른 던전 가기' → 어비스 목록에서 같은 어비스 → 우연한 만남 확인 → 입장하기. 인원은 패킷 파티 정보(`party_size` — 파티장 번호 뒤
  인원 칸, 파티원 들어옴·빠짐으로 고침). 리모콘을 켠 뒤 아직 모르면 그 판은 파티끼리, 어비스에 들어가면 알게 돼 그 판이 끝난 뒤부터.
  파티로 우연한 만남을 돌 때 파티 패킷이 어떻게 오는지는 아직 실측이 없다 (복구 신호 이름이 보여 받으면 로그에 남긴다).
- 누가 빠지면 (사용자 11-22 — 11-21 엔 누가 빠지든 끝냈다): 파티원이 빠지면 남은 인원으로 계속 (파티장은 4명이 안 되면 다음
  입장부터 우연한 만남). 파티장이 바뀌거나(넘김, 파티장이 나감 — 빠짐보다 먼저 같은 ms 에 온다) 내가 파티에서 빠지거나(나가기,
  어비스에서 혼자 먼저 나옴 — 나감 알림 없이 파티 없음 정보만 온다, party-1120b 20:05:33) 파티가 없으면 카드를 끝낸다. 판 도중이면
  그 판은 마저 하고 보상 화면에서 (`party.broken` · `PacketState.party_leader_at`·`party_gone_at`).
- 패킷: 파티 번호·파티장·입장 진행의 파티원 상태 (`PacketState.party_*`). 패킷이 없는 PC 는 화면 버튼으로만 본다.
- 레이드 고정 파티는 아직 없다.

### 필드 보스 (`mabi/tasks/field_boss.py`)
- 열리는 때는 매일 12:00 · 18:00 · 20:00 · 22:00 부터 30분 (`data/content.json` 일정). 그 밖에는 카드가 큐에서 기다리고(`tasks.READY`),
  열리면 돌던 카드를 끊어도 되는 자리에서 끊고 먼저 한다 (`cutpoint` → 큐 `cut_for_timed`). 끝나면 밀린 카드를 이어 한다.
  다만 고정 파티 카드(어비스·레이드 카드의 `partyRole`)가 돌 때는 끼어들지 않는다 (`Kind.cuttable`) — 같이 도는 사람이 기다리게 된다.
- 보스·난이도는 탭에서 고른다 (카드의 `fieldBoss` → `[field_boss]`). 한 캐릭터에 1~3분.
- 다른 사람들이 금방 잡아 '전투에 참여하지 않아 획득할 수 있는 보상이 없습니다' 면 영역을 나갔다가 다시 들어간다.
- 2026-11-09 12시에 6캐릭터로 확인.

### 임무 게시판 제작 스크롤 (`mabi/tasks/board.py`, 2026-11-19)
- 이멘마하·반호르·던바튼·콜헨(`[board] towns`) 게시판에서 '제작 스크롤: …' 카드를 이번 주 살 수 있는 만큼 산다 (카드마다 3개).
- 가는 길: 지금 마을(CLI `ChannelDisplayName`, CLI 가 답하지 않으면 패킷)이 그 마을이면 퀵 내비게이터 '일반' → '임무 게시판'
  (`arrival.quick_nav`) — 마을 안에서 지도를 열면 캐릭터 둘레만 보여 게시판이 화면 밖일 수 있다. 다른 곳이면 월드맵 → 마을 →
  지역 맵의 게시판 아이콘(그림 `map_board`, 가장자리면 끌어 옮김 — `worldmap.pick_icon`). 지금 마을부터 들른다.
- 상점: '임무 목록' → 대사 한 마디 → 카드. 살 수 있나는 카드의 '구입 n/3'·'일시 품절' 글자 (상점을 열 때 목록 패킷이 없다).
  카드 → 구입 창 → Shift+E(남은 수만큼) → 버튼이 '구입하기' 일 때만 Space (다 산 물품은 '구입 조건 필요 아이템 보기') →
  `shop.buy_ok` 패킷·구입 창 닫힘. 실패 패킷 `shop.buy_fail` 이면 멈춤. 목록은 더 안 내려갈 때까지 내린다.
- 상점이 열린 채 '대화 넘기기' 자리(오른쪽 위)를 누르면 골드 표시가 눌린다 → 상점이 보이면 대사를 넘기지 않고, 닫을 때는 ESC 부터.
- 구입 창이 열렸나는 아래 버튼 글자('구입하기'·'…아이템 보기')로만 본다 — 이름 칸 높이엔 목록 위치에 따라 카드 제목이 걸린다.
  지도 아이콘을 눌러 뜬 정보 창은 목록 칸 정보 창과 달라 '여기로 가기' 그림이 안 맞아 이름 글자로 본다.
  상점이 열린 채 끊겼다 이어 하면 그 상점에서 바로 산다.
- 2026-11-19 한 캐릭터로 네 마을 12종 실기 확인 (이동 약 2분·사기 약 30초씩).
- 끝냈나는 게임에 신호가 없어 이번 주(월요일 오전 6시 — `profile.game_week`) 캐릭터마다 다 산 마을을 `state/board-week.json` 에 적는다.

### 주말 어비스·레이드 (`mabi/tasks/weekend.py`)
- 토·일요일에만 있는 '주말에는 어비스!'·'주말에는 레이드!' 를 캐릭터마다 깬다. 일일 숙제 카드에 `only=['weekend_abyss', 'weekend_raid']`
  로 담겨, 실행기(runner)가 캐릭터마다 어비스 → 레이드를 마치고 다음 캐릭터로 간다. 판은 `AbyssRepeat`·`RaidRepeat` 그대로 (클리어만 셈).
- 던전·레이드·난이도·방식(혼자하기·함께하기)은 탭에서 고르고 카드의 `weekend` 가 `[weekend.abyss]`·`[weekend.raid]` 를 덮는다
  (카드 설정은 칸 안의 칸도 고른 키만 덮는다 — `runner._merged`). 판 수는 `runs` (어비스 3 · 레이드 1).
  `[abyss]`·`[raid]` 위에 덮으므로 뒤에서 돌기·흩어진 물길은 앞에서(`abyss.FRONT_ONLY`) 같은 설정이 그대로 적용된다.
- 깼는지: HUD 퀘스트 추적 칸(CLI `get_quests`)에 있으면 아직 안 깸 (목표 줄 'n/m' 이 있으면 남은 판만). 추적 칸에 없으면 — 창이 열렸거나
  로딩 중엔 통째로 비므로 깼다고 보지 않고 — 퀘스트 창(J) **이벤트 탭** 카드에 '진행하기' 가 있나 (2026-11-14 사용자 화면으로 OCR 확인).
  들어가기 전에만 본다 — 깼으면 넘기고, 진행도를 읽으면 남은 판만. 다 돈 뒤엔 창을 다시 열지 않는다: 반복이 결과 패킷으로 클리어를
  세어 판 수를 채워야 끝나므로 채웠으면 깸 (11-14 사용자, 실기에서 채운 캐릭터는 모두 깨져 있었다). 깬 카드는 목록에서 빠지고(버튼만
  없어져도 깸으로 봄), 이벤트 퀘스트를 다 깨면 **이벤트 탭이 통째로 없어진다** — 창은 열렸는데(아르바이트 탭 글자) 이벤트 탭이 없으면 깸.
  창을 보는 사이 NPC 가 말을 걸어 창이 닫히면 한 번 더 본다. 성장 가이드 주간 '어비스' 남은 횟수는 평일 판도 세서 쓰지 않는다.

- 카드 아래 오늘 진행: 다 끝났으면 '오늘 클리어', 아니면 '숙제 n/m'. 조건이 안 돼 넘긴 일이 남은 숙제('넘김(조건)' —
  아르바이트 가공·전달 물품 부족)는 끝난 것으로 세되 '넘김 n' 으로 따로, 풍선에 까닭 (`chars_api.today_of`, 사용자 11-22).

## 드레스룸 (`mabi/dress/`, `gui_app/dressroom.py`, `web/dressroom/`, 2026-11-15)
- 고치기 전에 `docs/DRESSROOM.md` (무엇을 기준으로 삼나·판 번호·깨졌던 것·전체 의상 점검 `tools/dress_audit.py` 와 기준선).
- 염색 탭 '드레스룸' 버튼으로 따로 뜨는 창. 체형(여성·남성·소녀·소년)·셰이프(기본·마름·통통·근육)를 고르고 부위별로 옷을 입혀
  칸 색을 바꿔 본다. 칸마다 재질 딱지(염색 탭과 같은 `dye_reach`), '프리셋으로'는 염색 탭 프리셋에 더한다. 고른 값은 settings 'dressroom'.
  염색 불가 옷(콜라보·부엉곰 깃장식 등)은 재질에 염색 키워드(_ISDYABLE_ON·_DYE_ON)가 없고 텍스처가 색 그림이라 그대로 그리고(FORMAT 8),
  카드엔 색 칸 대신 '염색 불가'.
- 염색 칸은 옷마다 최대 6칸이다 (FORMAT 10). 모델 정의 DyeInfo 의 배선(칸 → 메시·재질 칸·채널)을 `dress/dyeslots.py` 가 읽어
  재질마다 채널 0~2 가 받는 칸(`slots`)으로 싣는다. 상의는 3색 재질 둘(칸 0~2 · 3~5)이 많고, 칸이 섞이거나(0·4·5) 한 채널만 받는
  재질도 있다 (11-15 실측: 6칸 878 · 4칸 321 · 5칸 195벌). 배선 없는 채널은 재질 기본색 그대로. 예전엔 칸 i = 채널 i 로 앞 3칸만
  두 재질에 똑같이 칠해 격투가 클록 어깨가 주황이었다. 카드는 옷이 가진 칸 수만큼 보인다 ('프리셋으로'는 앞 세 칸).
- 칸마다 기본색은 게임 시트의 아이템 기본 염색(DyeColor0~5, 목록 `colors`)이 먼저, 시트에 없는 칸은 재질 기본색
  (`Dresser.defaultColors` — 입힐 때·기본색 되돌리기·색 기억 비교가 다 이것). 재질 기본색은 작업용 색이라 게임과 다른 옷이 있다
  (하이스쿨 크러쉬 유니폼: 재질 겨자색, 시트·아이콘 남색).
- 옷 색 기억: 옷마다 마지막에 칠한 색을 기억해(기본색과 다를 때만, `itemColors` 300벌) 다시 입으면 그 색으로 입힌다.
  머리는 바꿔도 전 머리 색을 칸 이름(Hair·Hair1·HairAccessory)대로 잇는다 (전 머리에 없던 Hair1 은 Hair 색).
- 별도 프로세스(`gui.py --dressroom`). 리모콘은 GPU 를 끄고 그리는데(`--disable-gpu`, 10-22 화면 엔진 충돌 때문) 그러면 WebGL 을
  못 만든다 (이 Qt WebEngine 에는 소프트웨어 WebGL 이 없다). 그래서 드레스룸만 GPU 를 켜고 따로 띄운다. Qt WebEngine 은 GPU 를
  자기 프로세스 안에서 돌리므로, 그래픽 드라이버 쪽에서 죽어도 드레스룸만 닫히고 리모콘은 그대로다.

- 아르바이트·요일 던전·대장간·접속 정리·끼어들기가 같이 쓰는 대화 처리. 대화가 지금 어떤지는 `dialogue.now(bot)` 하나가
  패킷·CLI·화면을 한 규칙으로 합쳐 `View` 로 돌려준다 (2026-11-22). 부르는 쪽은 그 값으로 할 일만 정하고 패킷 칸을 직접 읽지 않는다.
  - 대화 중: 패킷 → CLI(`IsDialoguePlaying`). 창이 열려 있나(open): 신호가 없으면 화면('대화 기록'·대화 넘기기).
  - 넘길 대사가 남았나(lines_left): 패킷 대본이 정한다 — 메뉴 없는 덩어리면 남음, 한 쪽짜리이거나 아직 안 누른 메뉴 덩어리면
    쪽 수로. 그 밖(여러 쪽 메뉴를 한 번 누른 뒤·패킷이 모름)은 넘기기 버튼(화면) → CLI(`IsDialogueNextAvailable` 이고 선택 대기 아님).

- 패킷 대본 (11-05 아르바이트 캡처로 확인): 대화는 덩어리(대사 진행 패킷) 단위로 오고, 선택지 알림이 같은 단계로 덩어리 바로 앞에 온다.
  덩어리 안의 대사 묶음(SJON) 에서 쪽 경계(`Next`) 수 + 1 이 쪽 수, `dialogueConditions` 가 덩어리가 나온 까닭(퀘스트 받기·목표 달성 …).
  선택지 알림을 못 받은 덩어리는 메뉴를 모름으로 둔다 (지난 덩어리 메뉴가 남지 않게).
- 넘기기 한 번이 덩어리째 넘긴다: 여러 쪽 대사도 한 번 누르면 끝나고(다음 덩어리·대화 끝), 메뉴 덩어리는 메뉴 쪽으로 건너뛴다.
  그래서 메뉴 덩어리는 누른 뒤 패킷을 기다리지 않는다 (예전엔 오지 않을 다음 단계를 3초씩 기다렸다). 누른 수는 덩어리마다 센다.
- 패킷 메뉴는 선택지 수로 본다. 대사 종류(확인·선택지·퀘스트 수락·퀘스트 목표 달성)를 '메뉴' 로 읽어 문게이트 정찰 결과 보고 뒤
  한마디(목표 달성, 선택지 0)를 메뉴로 알고 버튼만 기다리며 ESC 를 13분 눌렀다 (2026-11-22 → 아르바이트 실패 → 게임 다시 켜기).
  그 잘못 읽음을 CLI 가 몰래 덮고 있어 한 달 가까이 아무도 몰랐다 → 덩어리마다 한 번, 창이 그려지고 2초 지난 뒤 출처끼리 견줘
  어긋나면 실행 로그(INFO)와 관찰 기록(`judge.dialogue` — 패킷·CLI·화면 값)에 남긴다 (`View.audit`).
- 우리 메뉴가 아니면(버튼 글자에 결과 보고·수락이 없음) 버튼을 기다리지 않고 바로 ESC. 아르바이트는 메뉴 버튼 기다림이 3번 이어지면 그만둔다.
- 루틴만의 조작은 `talk`·`leave` 에 처리기(handlers)로 넘긴다 (예: 대장간 수리 창 ESC).

## 게임 단축키 (`mabi/keys.py`, `mabi/gamebinds.py`, 2026-11-19)
- 리모콘이 누르는 게임 키(여기서 나가기·카메라 토글·퀘스트 창 …)는 게임 조작키 설정을 따라간다. 게임은 바꾼 키만
  PlayerPrefs 'CustomKeys' 에 둔다 (LocalLow `devCAT\마비노기 모바일` 의 Base·Changed 파일, base64 + XOR — 형식은 gamebinds 머리말).
  파일이 바뀌면 다시 읽는다. 정하는 순서: 옵션에서 기본값과 다르게 정한 키 > 게임에서 바꾼 키 > 기본 키(게임 기본 주 키).
  게임 키가 리모콘 일시정지·염색 도우미 키와 같으면 쓰지 않는다. 동작 번호·게임 기본 키는 `data/game-rules.json` keybind.
- 조합 키('shift+esc')를 누를 수 있다 (`inputs.combo` — 보조 키를 누른 채 본 키). 뒤에서 도는 PostMessage 도 같은 순서.
- 콘텐츠 나가기(던전·어비스·레이드·출항선·보스 영역·여관)는 여기서 나가기 키(기본 Shift+Esc)를 먼저 누르고, 확인 창이
  안 뜨면 오른쪽 위 아이콘을 누른다 (`exits.Exit.open_dialog`). 레이드는 예전 보관함 키(X) 대신 이 키 — X 는 필드로 나가면
  보관함 이동이 이어졌다. 드릴은 결과 창 ESC 그대로. 카메라 토글 기본은 End (게임 기본 주 키, 보조 Z).
- 실기 확인 남음: 뒤에서 도는 중 Shift+Esc 가 PostMessage 로 먹는지.

- 넘기기 버튼(`Bot.skip_button`): '대화 넘기기'·'장면 넘기기' 는 같은 자리에 같은 글자라 그림만으로는 헷갈린다
  (2026-10-25 보스 출현 연출을 대화로 알아보고 눌러 게임이 앞으로 튀어나옴). 종류는 패킷 컷신·대화 중 → CLI 대화 중 → 그림 점수 순.
- 어비스·던전 중(`Bot.scene_skip` 꺼짐)이나 뒤에서 도는 중엔 연출을 누르지 않고 스스로 끝나길 기다린다.

  게임 시작 눌림은 패킷 게임 입장으로, 장소 이름(`space.game_space`)은 패킷 맵 이름으로 먼저 본다.

- 게임이 패치돼 패킷 표가 게임 메타데이터와 안 맞으면 패킷 감시가 꺼지고(`stale_table`) CLI·화면으로만 돈다. 표를 다시 묶어 새 판으로 낸다.
- 패킷 감시는 리모콘을 켜면 바로 켜져(`web_main` → `Api.packet_status`) 숙제를 안 돌려도 계속 돈다. 받은 이벤트 중 우리 판단에
  쓰는 것(`days.KEYS` — 출석 대화 시작과 관찰 기록: 로그아웃·접속·맵 진입·던전·사냥터·드릴 상태)만 게임 날짜(오전 6시)별 `logs\packets\<날짜>.jsonl` 에 남긴다 — 오늘·어제 것만 두고
  그 전 것은 지운다 (`packet_monitor/days.py`, 2026-11-17 사용자 '작업에 필요한 것만 체크·저장'). `PacketMonitor.today(key)` 가 '오늘 이 신호를 처음 받은 시각' 을
  답하고, 리모콘을 다시 켜도 오늘 파일을 읽어 안다. 줄마다 그때 접속한 캐릭터 번호·이름을 단다.
  숙제·이어 하기·출석은 하루 기록을 직접 읽지 않고 `mabi/observed.py` 한곳으로 묻는다 (2026-11-22).
  - 이어 하기: 일시정지 중에도 감시는 돌아, 멈춘 뒤 받은 것으로 끊긴 판이 끝났나를 본다 — 로그아웃·다른 캐릭터 접속·마을 진입이면
    끝남(`left_since`), 은동전 사냥터 클리어(`field_cleared_since`), 공물 심층 던전 클리어(`deep_cleared_since`). 답은 찾은 줄 ·
    False(빠짐없이 봤는데 없음) · None(모름 — 감시를 늦게 켰거나 흐름이 끊김, 예전 규칙으로). 멈춘 때는 `stopped_at` 하나를
    실행기('멈춘 뒤 관찰' 로그)와 끊긴 판 판단이 같이 쓴다.
  - 출석: 오늘 출석 대화 시작을 받았으면 출석은 지나간 것 (계정에 하루 한 번 — 11-17 은 06:47 첫 캐릭터에만). 작업을 시작할 때
    (`Bot.check_in` → `situation.check_attendance`) 넘긴 것으로 하고, 남은 출석 신호는 화면에 출석이 없으면 지운다.
  - 표 어긋남 기록(`logs\packet-날짜.log`, 패치 대응용)은 따로 14일 둔다.
- 패킷을 놓치지 않게 (2026-11-17 사용자 '비동기로 와서 간헐적으로 놓칠 수 있잖아'). 놓침은 두 가지다.
  - 볼 때를 놓침(받았는데 작업이 그때 안 봄): 받는 스레드는 늘 돌고 이벤트마다 번호를 붙여 둔다. 작업은 '지금 X 냐' 가 아니라
    '누르기 직전 번호(`input_mark`·`packets.mark`) 뒤에 X 가 한 번이라도 있었나' 로 묻는다 (`find`·`wait`·`saw`, `wait_packet(since=)`).

    (11-05 요일 던전: 500개가 27초 만에 찼고 그중 423개가 한 종류). 상태 사본(`history`)은 상태가 바뀔 때만 쌓는다.

    다룬다: 끊기면 맵·던전·이동 상태를 모름으로 돌리고 CLI·화면으로 본다. 출석처럼 패킷이 없으면 화면이 판단한다.

  접속 뒤 정리가 시간을 넘겨도 게임 안이면 이어 간다 (`login.settle_first_login`) · '게임 종료' 를 눌렀는데 창이 안 뜨면
  다시 누르고, 확인(Space)은 창이 닫히는 것으로 본다 (`Bot.to_charselect`, `press.until`) · 오류 뒤 정리는 메인 화면을 몇 초
  동안 몇 번 본 뒤에 다시 켠다 (`outcome.settle`) · 아르바이트 '진행하기' 뒤 추적 칸에서 첫 제목이 아니라 누른 일을 고른다
  (`arbeit._pressed_title`) · 점검자의 '모름 → 메인으로' 는 10분 지나면 다시 해 보고, NPC 메뉴 버튼 기다림은 15초 안에
  이어진 것만 센다 · 던전 '입장하기' 뒤 진행 신호를 못 봐도 던전 맵 안이면 (비용을 냈을 수 있어) 나가지 않고 이어 한다.

## 점검자 (`mabi/monitor/`)
태스크는 자기가 아는 순서대로 동작을 요청만 하고, 상황 판단과 대응은 점검자 한곳에서 한다 (2026-10-26 사용자 설계).
태스크마다 if 를 따로 두던 때는 한 곳에서 고친 것(작별 화면·출석)이 다른 태스크에 없어 같은 화면에서 또 막혔다.
- `detect.look()` — 지금 상황 한 단어: 로딩 · 캐릭터 선택 · 타이틀 · 나가기 질문 · 출석 · 던전 창 · 구하는 방법 ·
  필요한 아이템 없음 · 확인 · 전달 창 · 결과 보고 · 수락 · 가공 · 재료 전송 · 제작 · 제작 창 · NPC 대화 · 작별 대사 · 연출 · 보상 화면 · 화면 터치 · 쓰러짐 · 메인 · 모름.
  패킷 → CLI → 화면 순. 메인 HUD 가 보이면 창 템플릿을 건너뛴다 (한 번에 2초 → 0.03초).
  `situation.look()` 도 이것을 쓴다.
- `handlers` — 상황별 대응. 묶음이 넷: 어느 일이든(로딩·출석·작별·연출·대화·확인·화면 터치), 메뉴를 다루는 일(수락·결과 보고·전달·던전 창 —

## 게임 동작 메모
- 6시 이후 첫 접속 때는 메인 화면 전에 출석 이벤트 대화, '오늘의 스텔라 픽', 공지 웹 팝업이 나올 수 있습니다.
  `login.settle_first_login` 이 순서와 상관없이 처리합니다 (출석부 건너뛰기 / 가운데 카드 → 스텔라 픽 / ESC).
  접속하지 않고 6시를 넘기는 경우(어비스 반복 등)의 출석은 `situation.clear_attendance` 가 넘깁니다.
- 채팅 입력창이 열려 있으면 HUD 의 키 안내(ESC 등)가 사라져 메인 화면 인식이 실패합니다.
- 하루 초기화는 오전 6시. 6시 전은 전날로 칩니다 (`state/<날짜>.json`).
- 접속 전환을 너무 자주 하면 "인증 오류" → 접속 사이 최소 60초. 거듭 나면 접속을 더 시도하지 않고 멈춘다 (`AuthBlocked`).
- ASSIST(H, 우하단 자동 스킬)는 켜져 있어야 하고 봇은 건드리지 않습니다.
- 검은 구멍은 입장 즉시 횟수가 차감되므로 도중에 나가면 안 됩니다.
- 추가 루팅은 요일 던전에만 있고 3회 모두 합니다 (골드 6천/1만2천/1만8천).
- 일요일 요일 던전(2026-10-25 실측): 카드 진행하기가 마을 임무 게시판으로 가서 대화로 빛나는 동굴(골드)·눈부신 저택(보석)·찬란한 유적(촉매) 중 고른다. 고르면 카드 목표가 그 던전으로 바뀌고, 진행하기를 다시 누르면 평일과 같은 던전 창이 열린다. 고를 던전은 숙제 기본값 `[weekday_dungeon] sunday`, 캐릭터별 `[weekday_dungeon.sunday_by_slot]`.
- 클리어 후 NPC 대화는 모험가 길드 주간 정기 의뢰 조건(심층 3회 / 일반 5회 / 사냥터 5회)을 채웠을 때만 나옵니다.
  봇은 대화가 있으면 넘기고, 없으면 그냥 지나갑니다.
- 사냥터 클리어 화면에서는 CLI 퀘스트 목록이 비어서 나옵니다. 사냥 퀘스트가 3번 연속(약 15초) 없어야 클리어로 봅니다.
- CLI `get_activity` 는 로딩 중 오류를 내고, 지역 이동 중에는 `IsAutoTraveling` 이 false 가 됩니다.
  도착은 장소 이름이나 템플릿으로 판단합니다.
- 캐릭터 선택 화면 카드: 선택된 카드는 노란 테두리·금색 배경에 얼굴 확대 그림. 카드 아래 이름 → 접속 시간 → (대표 캐릭터) → 재화 순.
  스크롤 맨 아래에서 마지막 줄이 화면 아래 어두운 띠에 걸리면 이름 글자가 회색이 된다.
- 메인 화면으로 돌아올 때·싸우는 동안 포만감이 `[game] eat_at`(기본 4% — 먹힌 가장 높은 값) 이하이면 음식을 하나 먹는다 (B).
  게임 설정 '음식 바로 먹기 버튼 표시'(기본 25%)는 버튼만 띄우고, 게임은 포만감이 바닥 가까이여야 먹게 해 준다
  (2026-11-22 실측: 25~6% 에서 B 는 안 먹히고 4·3·2·0% 에서 먹힘 — 먹은 뒤 포만감은 100 + 남은 값). 포만감은 CLI `get_my_info` 의 Vitals 로 30초마다 묻고, CLI 가 답하지 않을 때만 화면의 배고픔 표시로 본다
  (패킷 포만감은 먹을 때만 온다). 캐릭터 자동 설정으로 선택 화면에 나갈 때도 일어난다.
- CLI `get_my_info` 에는 캐릭터 이름이 없다 (Title = 착용 타이틀, RealmName = 서버).
- 봇은 화면을 캡처해서 인식하므로 다른 창이나 Windows 알림이 게임을 덮으면 실패합니다.
  캡처 전에 게임 창을 앞으로 가져오지만, 알림은 그래도 위에 뜨므로 **방해 금지 모드**를 켜 두세요.
  다른 프로그램의 항상 위 창(데스크톱 메이트 등)이 지역 맵 목록 같은 자리를 가려도 고르지 못한다 (2026-11-14).

## 작업 큐 (`mabi/workqueue.py`, `gui_app/queue_api.py`)
- 큐의 주인은 파이썬. 화면(web/queue.js)은 'mm:queue' 상태를 그리고 버튼만 보낸다 → 화면을 다시 띄워도 큐는 안 끊김
- 카드 종류: daily(일일 숙제 — 주간·기타 숙제도 `only` 로) · abyss · raid(반복) · goal(제작·채집·가공 목표) · action(버튼 하나 = 명령 하나, 전체 수령) ·
  enhance(각인 강화 반복) · restart(게임 다시 켜기 — 리모콘이 올린다)
- 지도 이동: 패킷으로 다른 마을에 있는 걸 알면 지역 맵 목록을 건드리지 않고 바로 월드맵으로 간다.
- 던전 클리어 뒤 '화면을 터치해 주세요': 패킷이 클리어를 알면 2.5초마다 터치 (예전엔 6초씩 기다렸다). 글자·그림이 보이면 Space (2026-11-19 사용자 — 던전·사냥터·어비스 모두 넘어간다, 뒤에서 돈 어비스 로그로도 확인), 안 보이는데 누를 땐 앞이면 빈 곳 클릭 — 메인 화면의 Space 는 자동 전투다 (`clear.tap_blank`).
- 파란 버튼 = 지금 바로 (맨 위에 넣고 돌던 것은 대기로 밀었다가 이어서), '목표' = 맨 아래에 담기
- 일시정지 = 돌던 동작을 잠깐 멈춤. 맨 위 한 장만, 큐는 일시정지 카드에서 선다, 껐다 켜면 대기로 (하던 자리 기록은 유지). 카드 메모에 멈춘 숙제를 적는다 ('[캐릭터] 아르바이트부터 이어서')
- F12 하나로 전체: 돌고 있으면 무엇이든 일시정지(지금 명령도 끊음 — 날개가 들어도 멈춤 우선), 쉬고 있으면 맨 위 일시정지 카드 이어 하기
- Shift+F12 = 지금 카드만 중단 (빼고 다음 카드로), Ctrl+F12 = 전체 중단 (큐를 비움). 숙제의 '게임 조작 시 일시정지'는 Shift·Ctrl 만 누른 것을 조작으로 보지 않는다
- 더 할 수 없는 카드(재료가 다 떨어짐 — `OutOfStock`)는 실패로 기록하고 큐에서 빼고 다음 카드로 (멈춤 이유 `drop`, 2026-11-15).
  생활 스킬 레벨 부족은 실패로 남고, 분해된 장비 부품 부족은 일시정지로 남는다 (사람이 채우면 ▶).
- 화면 설정 맞추기는 큐 한 번에 한 번, 할 일이 다 끝나면 되돌림
- 제작·채집·가공 카드(goal·action)의 캐릭터: 카드의 '캐릭터:' 줄에서 고른다 (`queue_api.card_character`). 기본은 접속 캐릭터 — 목표 카드는
  처음 집을 때의 캐릭터를 기억(pin)해 두었다가 다른 카드(필드 보스처럼 여러 캐릭터를 도는 카드)에 밀렸다 돌아오면 그 캐릭터로 접속을 바꿔 이어 한다
  (보유량·가공 칸이 캐릭터마다 다르다). 슬롯을 고르면 시작할 때 그 캐릭터인지 보고 아니면 접속을 바꾼다. 한 번 하는 행동은 접속 캐릭터면 확인 없이 바로
- 카드 진행 줄(Kind.view — 지금 하는 일·단계·막대)은 파이썬이 만들고 카드와 오버레이가 같이 그린다. 숙제는 runner 의 character·task_start·step·task_end 이벤트로 채운다
- 결과 창 (`mabi/queue_report.py`): 큐를 시작한 뒤 남은 카드(대기·진행·일시정지)가 없어지는 순간 한 번 — 다 끝남·전체 중단·마지막 카드 뺌.
  일시정지는 도는 중으로 친다. 요약 탭(카드별 결과 + 합친 얻은 것·재화·쓴 것) + 카드마다 탭 (숙제는 캐릭터별). 지난 결과는 큐의 '결과' 버튼
  - 얻은 것: CLI get_items(소모품·재료, 가방+보관함 합계) · get_currencies 를 앞뒤로 찍어 뺀다. 숙제는 캐릭터마다(접속 뒤 ~ 그 캐릭터 끝), 나머지는 카드 앞뒤.
    그 사이 사람이 직접 한 것도 섞인다. 장비·의상은 안 나온다
  - 오늘 이미 끝나 건너뛴 캐릭터는 결과에 넣지 않는다
- 작업 큐 오버레이 (`gui_app/queue_overlay.py`, 옵션 → 작업 큐 오버레이, 기본 켜짐): 게임 구석에 진행 상황. 캡처 제외(봇 화면 인식에 안 찍힘)·클릭 통과·포커스 안 가져감.
  배경(반투명 판/없음)·불투명도·글자 크기·구석·여백·다음 카드 수
- 다른 프로그램용 명령 통로 (`gui_app/control.py`, 파이프 `MobiRemote-control`): 상태(큐·게임 창·연결 제한 — 조회 명령을 부르지 않는다)·
  선택지 묻기, 일시정지·이어 하기·카드 넣기 같은 조작. `watch` 를 보낸 연결에는 카드 시작·끝, 큐 끝, 질문을 알린다.
